# Local operations

Run `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=source python3 -m unittest discover -s tests -v`. Use relevant scoped checks during development; reuse PASS while content, declared inputs and environment match. Close a coherent source change and commit it before `python3 scripts/install_global.py`. Installation builds `~/.codex/harness/venv`, checks module hashes and records the source revision in `~/.codex/harness/installation.json`. Verify composed global instructions, active hook command and fresh Codex consumer behavior separately. `CODEX_HOME` selects an isolated installation for tests. Changed non-managed hooks require native trust; a vetted one-off CLI invocation can verify them with the documented hook-trust option, but does not establish persistent desktop trust.

Global common and host instructions compose into one managed region while preserving other global prose. Unrelated hook groups survive installation. The exact previously deployed managed region and command are replaced; no permanent backup or legacy runtime mode is created. Keep an old install only while a live consumer references it. After new-hook/fresh-session confirmation and old-session retirement, remove only the verified harness-owned old install/state. Do not delete the interpreter servicing an active hook.

Native UserPromptSubmit binds `/tmp/harness-sessions/<session_id>`. Inspect its state, events, raw tools and frozen packages internally. Pasted-request attachments are included in every relevant request turn. Use `harness LEDGER confirm-request INTERPRETATION.json` for subsequent turns, classifying changes and separating scope from priorities. `add`, evidence-backed `transition`, and guarded `replace` maintain typed state. A correction preserves task identity/history; update or supersede requirements deliberately.

At a meaningful candidate boundary, use `assess-review ASSESSMENT.json` (candidate_revision, change_types, semantic_risk, reason) and `schedule-review CANDIDATE.json` (artifact_refs, aggregate_diff, resulting_state with frozen content). PostToolUse also schedules after a current assessment. Give the returned frozen file to a fresh native child, then continue independent work. Ingest result/receipt with `ingest-review`; use `disposition` for findings and actual resolving evidence. `prepare-review` remains a direct transport entrypoint for explicit frozen review. Scheduling never claims Python can launch or cancel Codex children.

Before expensive checks, `select --proposed ACTION.json` can choose reuse. `add verification_plans PLAN.json` binds exact command, scope, target_identity, input_identities and execution_environment; related_inputs and repeat_reason are optional. Recognized test commands get conservative repository identity automatically. PreToolUse blocks an identical matching latest PASS; use new_evidence/new_hypothesis/prior_result_followup only when real. Unknown/running results are not PASS. Continuation tools exposing session_id are associated with the initiating command and identity; a tool surface that omits that metadata needs explicit scoped completion evidence. Native process cancellation is coordinator-owned; noncancelable obsolete results need not be awaited.

Before a commit, `replace commit_scope UNIT.json` records candidate_revision, scope, message and remaining_required_work. The unit must be closed; no full-suite prerequisite is added. `complete`, `progress` and `select` inspect parent readiness independently of commit readiness. Instruction changes additionally require whole-file recomposition evidence and consumer checks; global fragment records identify the installed source revision. Local AGENTS is consumed locally.

`scratch NAME` creates a marker-proven task temporary directory under the ledger. `cleanup`, cancellation and completed Stop clean those directories only; preserve necessary evidence separately. New tracked paths require an artifact persistence decision (repository_paths plus persistence: separate_file, repository_placement, git_tracking, durable, future_consumer, maintainer, convention, contract, alternatives, reason). Keep one-off analysis/review notes in existing task storage, not a new repository report/ignore/archive hierarchy. Containers/networks/DBs created by a task need explicit provenance and cleanup through their native tools. Recovery checkpoints occur at PreCompact/SessionEnd, not every tool. Recovery copies expire after seven inactive days and are pruned only with harness markers; unmarked old archives require an ownership audit before retirement. This retention is a recovery policy, not permanent history.

PermissionRequest matches nonempty communication, actual endpoints and a live dispatched delegation; unmatched requests retain native permissions. A delegation record does not grant user authority to message others. CI covers contract and isolated installer/platform tests. Real native concurrency, hook trust and fresh consumer behavior require observed Codex runs. See [official hooks](https://learn.chatgpt.com/docs/hooks) for event/output and trust contracts. Historical evidence is under `history/` and `eval-results/`; it does not claim current acceptance.
