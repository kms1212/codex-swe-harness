# Local operations

From the repository root, run `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=source python3 -m unittest discover -s tests -v`. Commit a clean source revision, then run `python3 scripts/install_global.py` to install into the current user's global Codex environment. The installer verifies source and installed module hashes and writes `~/.codex/harness-v0/installation.json`; inspect this manifest with `git rev-parse HEAD` when checking the active revision. Codex requires interactive trust of a changed non-managed global hook definition through `/hooks`. The current hook definition has been trusted. No account API key is needed because native child review is dispatched by Codex, not a Python API client.

The installer detects the host OS and composes `runtime/instructions/common.md` with `macos.md` or `linux.md` inside a marked region of `~/.codex/AGENTS.md`. It preserves text outside that region, replaces only the managed region on update, and migrates the exact prior harness-owned file. `installation.json` records `host_os`, `instruction_fragments`, paths, hashes, and the Git revision. Set `CODEX_HOME` to install into an isolated configuration for verification. macOS instructions keep temporary paths spelled `/tmp`, including when the OS resolves them to `/private/tmp`.

The `PermissionRequest` hook approves a communication request only when its tool, nonempty payload, sender, recipient, and a `DISPATCHED` delegation record match. Parent-to-worker messages and worker-to-parent returns are supported. An unmatched or malformed request emits no decision, so Codex uses its ordinary approval flow. Approved requests are recorded with their request ID, direction, endpoints, delegation ID, and payload hash. Review the `permission_request_observed` and `delegated_communication_approved` events and raw permission input when diagnosing a session.

GitHub Actions runs the contract tests, isolated installer lifecycle tests, platform selection tests, permission policy tests, package build, CLI and hook entrypoints, and isolated installer entrypoint on `ubuntu-latest` and `macos-latest`. CI does not prove trust of a changed global hook or real multi-thread delivery; those require a fresh local Codex session.

Verification records may include `target_identity`, `related_inputs`, and `execution_environment`; completion requirements may set `scope_identities` and `scope_environments` by scope. A matching PASS remains reusable across a commit or unrelated change because its content identity remains the same. A changed identity or environment requires a new check for that scope. Legacy records without scoped identities retain the revision check. `progress` reports duplicate expensive actions, cancelable running work with equivalent PASS evidence, and independent work pairs. The Stop hook records its review-path choice; a deterministic one-line edit takes a lightweight path, ordinary code takes scoped checks, and semantic-risk changes retain native review.

Create a ledger with `harness-v0 LEDGER create TASK_ID OBJECTIVE ORIGINAL_REQUEST`. Its authority policy starts unspecified; record the actual model with `replace authority FILE`. Add typed JSON records with `add SECTION FILE`; replace integration/completion/authority with `replace SECTION FILE`. `prepare-review CANDIDATE.json --type architecture --source REF` freezes a package and returns the request to send to a native semantic-review child. For code-only changes with compatibility, cross-artifact, or other semantic risk, add `--semantic-risk`; this makes review required. Once required, later review preparation retains that requirement and all previously required change-type criteria until the integrator explicitly replaces completion state. After the child returns, save the structured result and native receipt, then run `ingest-review PACKAGE RESULT ACTIVATION`. Use `disposition REVIEW_ID INDEX accepted EVIDENCE_ID` after repair. `complete` and `progress` inspect the parent state. The record files and CLI calls should be generated from the actual task, not copied from a challenge fixture.

For an active session, inspect `/private/tmp/harness-v0-sessions/<session_id>/state.json`, `events.jsonl`, raw tool records, and frozen packages. The archive under `~/.codex/harness-v0/archive` restores a ledger if its transient copy is gone. Preserve failed checks followed by repairs. Invalid reviewer responses require a corrected structured result or a fresh review; the append-only event history is retained. The older `runtime/stop_hook.py` and `runtime/hooks.template.json` remain isolated test fixtures; the installed always-on entry point is `harness_v0.always_on`. Official [Hook documentation](https://learn.chatgpt.com/docs/hooks) describes trust and Stop semantics.
