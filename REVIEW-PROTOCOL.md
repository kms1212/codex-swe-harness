# Semantic review protocol

A frozen evidence package contains original request, complete ordered request history, current confirmed interpretation and commitments, decision history, authority, epistemic/work/integration/artifact state, current candidate diff and resulting file contents, verification chronology, unknowns and applicable rubric. Sorted compact UTF-8 JSON with a trailing newline defines its SHA-256 receipt. Packages are immutable; concurrent replacement gets a new ID.

Risk assessment belongs to `scheduling`, independently of `SemanticReview.review(package, projection) -> ReviewResult`. It records current candidate, semantic request revision, change types and rationale for additional review protection. Number of files and extension are not risk. At stable execution boundaries, coalesce events and dispatch one fresh critic while continuing independent work. Current matching coverage is reused. Stop-time catch-up is fallback for missing, failed or late coverage.

The built-in adapter writes the package and returns a handoff for Codex native collaboration. It cannot spawn from Python. Give the child only that package and a neutral evaluation instruction, without generator confidence or a desired verdict. Require independently computed package hash, review ID, adapter, structured findings, overall risk and unknowns. Each finding includes rubric criterion, severity, evidence refs, violated requirement, blocking flag and confidence. Invalid schemas are result failures; missing activation is a transport failure.

The child is instructed not to modify artifacts. The available native spawn API does not remove write capabilities; activation records explicitly say instruction-level isolation. A observed lack of writes cannot establish capability-level read-only. The adapter cannot independently prove exclusive child context.

Results apply to frozen candidate/context, even when returned after main has changed the candidate. Receipt ingestion never stamps old review with current coverage. Current matching coverage can be any matching review, not merely the latest returned result. Pending obsolete reviews do not prevent scheduling current coverage. Findings remain traceable and must be consumed. Accepted repairs require a later PASS explicitly resolving `review-id:index`; criterion 14 also needs consumer-point evidence. A finding absent from current content may be marked superseded only with a current targeted PASS. A new semantic candidate still needs its own coverage.
