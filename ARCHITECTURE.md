# Purpose-built Codex SWE harness

Codex chooses and runs implementation tools. The harness owns state, provenance, review scheduling and completion enforcement. Existing implementation and historical evaluation are evidence, not authority for the user's intent.

## Semantic owners and execution

Global common instructions own general SWE judgment, modality and economy. Host fragments own execution details. Repository AGENTS owns development facts. `core.py` owns request history, current interpretation, obligations, decisions, authority and evidence. `always_on.py` owns hook ingestion and capture; `commands.py` recognizes bounded command semantics. `scheduling.py` owns candidate-bound risk assessment, coalescing and coverage. `review.py` owns immutable packages, rubric projection and the transport-neutral `SemanticReview` contract. Reviewers detect defects in the supplied snapshot. `completion.py` owns the parent gate; `lifecycle.py` owns proven harness scratch cleanup. Historical facts live under `history/` and `eval-results/`.

A user turn appends its substantive content. The integrator confirms its relationship to current scope and priorities. An unreflected turn blocks completion. Material corrections reopen commitments and invalidate semantic coverage; a no-change acknowledgment preserves coverage. Request history is always included in a frozen package, including pasted-request attachment contents.

The integrator assesses semantic risk and additional protection at a stable candidate boundary. Scheduling freezes one pending package, while further events coalesce. PostToolUse can deliver a dispatch request; the integrator starts a fresh native child and continues independent work. A changed candidate makes pending coverage obsolete. A later assessment schedules current coverage; a late old result remains history and must be consumed or explicitly superseded with current evidence. Stop normally checks current assessment, coverage, findings and remaining evidence. Missing coverage may trigger catch-up scheduling.

Python hooks cannot invoke native collaboration tools or cancel their processes. Native dispatch and cancellation remain with Codex. Collaboration dispatch returns before child completion, allowing overlap. Scheduling is not a background Python model service. The native reviewer shares available tool capabilities: “do not edit” is an instruction, not a capability guarantee. Activation receipts attest the observed child and package hash; they do not prove exclusive context or correctness.

## Identities and lifetime

Verification compares target content, declared related inputs, scope and environment. Candidate identity hashes resulting repository content, so committing unchanged bytes preserves evidence. PreToolUse prevents identical expensive checks with matching latest PASS; a later matching failure or declared repeat reason permits new work. Explicit plans support scopes beyond recognized tests. When tools expose a session ID, continuation results retain the initiating verification identity; starts are UNKNOWN until completion. Tool surfaces that omit exit/session metadata require explicit observable confirmation and remain UNKNOWN when no result can be established. Native start events expose no dispatch correlation key, so starts remain unclassified and block completion as live work. A schema-valid native package receipt reconciles the reviewer identity and consumes that transport work; ordinary worker returns remain separately integrated. Spawn/start order never determines role. Unknown command/results stay UNKNOWN. No shell parsing project or automatic inference of user meaning is attempted.

Commit scope closes known required work within the claimed change unit, independently of full-suite or release verification. Native commit interception consults that declaration; semantic completeness and truthful messages remain the integrator's judgment.

Session state lives at `/tmp/harness-sessions/<session_id>`. Recovery checkpoints are written at PreCompact and SessionEnd to `~/.codex/harness/recovery`, with seven days of inactivity retention. Per-tool mirroring and permanent backup folders are removed. Retention, file creation, repository placement, Git tracking, durability and cleanup are separate decisions. Artifact persistence records identify a continuing semantic owner, future consumer, maintainer, contract/convention and alternatives considered. One-off reports and review output stay in ledger/scratch; maintained contracts update their existing owner. Final user results are not automatically scratch or repository artifacts. Cleanup deletes only marker-proven harness recovery or explicitly created ledger scratch; unknown directories are preserved. User/external resources remain governed by their original authority. Container/network/DB cleanup is performed by Codex with proven task ownership, not an invented generic resource framework.

## Installation and boundaries

The package/module, CLI, environment variables, live install and managed marker have no development-stage version suffix. Python packaging retains its required version field. Ledger/review `schema_version` describes persisted JSON read separately from the producing run; it is not a runtime mode. Raw historical labels remain unchanged.

The installer builds the replacement at `~/.codex/harness/venv`, verifies source/module hashes, then publishes composed instructions and hooks while preserving unrelated content. The deployed old managed marker is migrated once. No old runtime shim is installed. Retirement of `~/.codex/harness-v0` requires fresh new-hook evidence and absence of live old-path consumers; the initiating session may still reference it. Hook trust is a Codex boundary, separate from installation. [Official hook documentation](https://learn.chatgpt.com/docs/hooks) specifies native event and trust behavior.
