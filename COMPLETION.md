# Parent completion and liveness

The gate returns COMPLETE, CONTINUE or BLOCKED. It requires the latest user revision to be interpreted, current parent commitments satisfied with known evidence, completed work integrated, delegated results consumed, no unresolved integration dependencies, required latest matching verification and consumer evidence, instruction recomposition/installation, current semantic review coverage when selected, and finding dispositions with targeted repair evidence.

Coverage binds candidate bytes and semantic request/context, rather than commit identity or review arrival order. A no-change user acknowledgment preserves coverage; a changed requirement invalidates it. A stale result cannot substitute for current review. Superseded findings require current targeted evidence; accepted blocking findings require post-review PASS and consumer evidence for criterion 14. Selection and a review verdict cannot remove obligations. Latest relevant FAIL hides an earlier PASS until repaired.

Stop reconciles observed candidate identity, confirms request freshness and current risk assessment, then checks coverage and gate reasons. Execution-time review is the normal path; missing coverage can schedule catch-up. Read-only turns with no task artifact change require no review/recomposition/install, even with preexisting dirty files. Cancellation stops remaining work and cleans only proven harness scratch; native workers need coordinator interruption when supported.

BLOCKED names an external input only when all remaining commitments/work are explicitly linked to it and no independent local gate work remains. Otherwise CONTINUE names actionable reasons. COMPLETE needs at least declared commitments, a candidate and verification scopes. The model remains responsible for faithfully translating natural-language requirements, honest commit scope, actual content references and evidence. The runtime can detect an unacknowledged turn, not independently judge every semantic interpretation.
