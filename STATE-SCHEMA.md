# Canonical state

`state.json` and append-only `events.jsonl` belong to the task. `schema_version` records a persisted format boundary. Snapshot writes are atomic; CLI and hook writers serialize through the ledger lock. Workers return results to one integrator, rather than editing parent state independently.

`request_history` preserves ordered revision, turn ID and substantive content, plus each confirmed interpretation. `original_request` is immutable history. `request_state` records interpreted-through revision, semantic revision, summary, full scope and separate priorities. `confirm-request` must cover the latest revision and classify none/add/remove/modify/priority/cancel, with a rationale. No-change confirmation preserves semantic state; other changes reopen satisfied commitments. Optional obligation updates use stable IDs; removed commitments remain REJECTED or SUPERSEDED history. Unconfirmed turns block the gate even when old evidence passes.

Obligations require resolving evidence. Work items distinguish DONE from INTEGRATED. Delegations require return, consumption and integration. Blockers identify exact external inputs and linked obligations/work. Integration owns candidate changes, integrated changes, conflicts and dependencies. Decisions retain supersession; epistemic records distinguish FACT, INFERENCE, UNKNOWN and USER_ASSERTION. Authority starts unspecified and preserves actual default admissibility, closure, capabilities, constraints and side-effect/delegation scope.

Evidence records producer, operation, observable result and references. Ordered verification records include status, target content, related input identities, scope, environment and consumer point when needed. `verification_plans` binds an explicit command to that identity and any justified repeat. The latest matching failure prevents reuse of an earlier PASS. Required scopes cannot be narrowed by action selection. Commit events do not invalidate content-based identities.

`review_schedule` stores candidate/request-bound assessment and immutable request receipts. Pending current review blocks completion; obsolete pending coverage can be replaced at a new assessed boundary. Review results carry candidate/context coverage, activation receipt, findings, dispositions and verification cutoff. A superseded finding requires a PASS on current content explicitly resolving its review/index. A changed candidate never inherits the old verdict merely because the old defect was removed.

Artifact records declare semantic role, owner and lifetime. Optional persistence decisions independently name separate-file creation, repository placement, Git tracking and durable retention, with future consumer, maintainer, repository convention, project contract and alternatives considered. Native Git-add interception requires a justified persistence record for newly tracked paths; groups of paths can share one continuing owner. Useful information alone cannot satisfy that boundary. `resources` records only explicitly created harness scratch with marker proof. Lifecycle records active/cancelled state. `commit_scope` declares candidate identity, semantic scope, actual message and remaining required work; it is not a verification checklist.

Instruction edits track each affected path and content identity. `instruction_changes` ties that identity to its requirement, owner, existing principle, integration, displaced guidance, whole-file evidence and current consumer check. Global fragments additionally require the active installed source revision. Local AGENTS edits require local consumption. Recomposition, review and installation records are distinct.
